# VSR-FOR-001 R0.8 — Approved Staging Provider Preflight

**Status: DRAFT / CONTRACT ONLY.** No live service endpoints have been identified or contacted. Passing this preflight is **not** evidence of a real Genesis registration, DigitalMe sign-in, Warden permit, RiverOS receipt, engine qualification, audit approval or deployment.

## Purpose

Add a deliberately limited integration seam in \`phase8_provider_probe.py\` for four future independent provider services:

| Role | Discovery responsibility | Not implemented |
| --- | --- | --- |
| GENESIS_REGISTRAR | Staging service identity, supported discovery version | Framework registration or source validation |
| DIGITALME | Staging service metadata and pinned issuer identity | Principal authentication, consent or mandate |
| WARDEN | Staging service metadata and pinned issuer identity | Policy decision or navigation authority |
| RIVEROS | Staging service metadata and pinned issuer identity | Evidence ingestion, signed receipts or reconciliation |

All four must have distinct pinned Ed25519 test verification keys and distinct issuers. The operator must provision these anchors **outside** the metadata returned by the service.

## Preflight contract

- Only GET \`/.well-known/vsr/knowledge-roads\` at a separately approved **HTTPS** hostname on port 443.
- No query, credentials in URLs, redirects, mutable operation, OAuth authorization request, engine execution or RiverOS POST.
- A per-role unpredictable 192-bit nonce and request fingerprint bind the response to role, URL and exact Git commit SHA.
- Returned JSON is capped at 32 KiB, must have \`application/json\` content type and a role-specific Ed25519 signature with the \`VSR-FOR-001-R08-PROVIDER-PREFLIGHT\` domain separator.
- The signed payload must include issuer, staging audience, \`navigate.readonly\` capability, status, service version, issued/expiry times (at most two minutes), echoed nonce, request digest, exact commit, and classification \`READONLY_SERVICE_METADATA\`.
- Enforce exactly the approved set of four provider roles. Missing configuration, failed GET, signature failures, stale clocks and any mismatch fail closed.
- A \`SIGNED_METADATA_PREFLIGHT_COMPLETE\` disposition is a **structural test outcome only**: all operational permission flags remain false.

## Security boundary

URL filtering is **not sufficient protection from SSRF, DNS rebinding, or a compromised DNS resolver**. The HTTP transport may only be enabled within a separately administered staging network with:

1. Egress firewall or gateway that restricts DNS-resolved destination IPs and prevents connections to loopback, link-local, metadata, private or administrative networks except specifically reviewed target ranges.
2. Validated TLS chain and hostname, approved CA trust and optional independent mTLS client identity.
3. Secrets and signed-key material stored in a managed secret service, never in GitHub files, test snapshots or frontend code.
4. Pinned registrar/identity/Warden/RiverOS issuer keysets, rotation, revocation, certificate renewal and clock source.
5. Route scope and principal verification **beyond** this metadata probe, governed by separately reviewed Warden \`navigate.readonly\` policy.
6. Durable request idempotency, fail-closed replay and true RiverOS evidence, with operator approval and rollback.

No wildcard hostnames, domains generated by the user, public VSR URLs, arbitrary ports, redirect targets, localhost URLs or local machine access are accepted by this contract. Host allowlists must be independently approved and never populated from incoming requests.
